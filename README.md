# procbot — личный Telegram-бот против прокрастинации

Закрытый помощник для **одного** владельца: помогает планировать день, вовремя начинать
задачи, дробить сложное на шаги, разбираться, что мешает, и не засыпает напоминаниями
(строго не больше четырёх за любые 60 минут, тишина и пауза соблюдаются). Ядро работает
без ИИ; ИИ только предлагает действия, а важные изменения всегда требуют подтверждения.

## Статус этапов

| Этап | Содержание | Статус |
|---|---|---|
| A — устойчивое ядро | Авторизация, БД и миграции, задачи и проекты, подтверждения, кнопки, таймеры, расписание и привратник уведомлений, тишина/пауза, восстановление после перезапуска, бэкапы, тесты | в работе |
| B — интеллект планирования | Голос, ИИ-шлюз с несколькими провайдерами, утренние планы, декомпозиция, анализ прокрастинации, память | в работе (ИИ-шлюз) |
| C — полный функционал в чате | Google Calendar, привычки, цели, недельная аналитика, приватность | не начат |
| D — Mini App | Визуальный интерфейс поверх того же API и базы | не начат |

## Быстрый старт

Нужны Python 3.12+ и [uv](https://docs.astral.sh/uv/).

```sh
uv sync
cp .env.example .env
uv run procbot gen-key        # вставить в MASTER_KEY
# заполнить TELEGRAM_BOT_TOKEN (от @BotFather) и OWNER_TELEGRAM_ID
uv run procbot migrate
uv run procbot run            # или просто `uv run procbot`
```

### Docker Compose (VPS)

```sh
cp .env.example .env && chmod 600 .env     # заполнить токен, ID владельца, MASTER_KEY
docker compose up -d --build
curl -s http://127.0.0.1:8080/healthz
```

Ровно один экземпляр: long polling нельзя запускать дважды (бот сам откажется стартовать
второй раз). Подробности, тома, обновление — [`docs/deploy.md`](docs/deploy.md).

## Команды

В Telegram:

| Команда / кнопка | Что делает |
|---|---|
| `/start` | Меню и короткое знакомство (часовой пояс, утро, вечер, тишина, цели — всё можно пропустить). Повторный `/start` ничего не сбрасывает |
| `/settings`, «⚙️ Настройки» | Часовой пояс, будни, сон, часы тишины, утро/вечер, недельный обзор, уведомления, ручная пауза, характер бота, напоминания, рабочие сессии, память и автономность |
| `/status` | Версия, время работы, база, число запланированных напоминаний, последний бэкап, состояние ИИ и календаря |
| `/help` | Справка по разделам |
| Меню | 📅 Мой день · ➕ Добавить · 📋 Задачи · ▶️ Начать работу · 🎯 Проекты/цели · 🔁 Привычки · 📊 Отчёт · 🧠 Память · ⚙️ Настройки |

CLI (`uv run procbot <команда>` или `docker compose exec procbot procbot <команда>`):

| Команда | Что делает |
|---|---|
| `run` (по умолчанию) | Запуск бота: блокировка единственного экземпляра → миграции → восстановление → polling + планировщик + `/healthz` |
| `migrate` | Применить миграции Alembic до head |
| `gen-key` | Сгенерировать `MASTER_KEY` (Fernet) |
| `backup` | Сделать зашифрованный бэкап сейчас (можно при работающем боте) |
| `verify-backup <файл>` | Расшифровать и проверить целостность бэкапа |
| `restore <файл> [--target путь] [--force]` | Восстановить базу; без `--force` не перезаписывает существующую, при `--force` сохраняет страховочную копию |

Обёртки: `scripts/backup.sh`, `scripts/restore.sh` (с `PROCBOT_DOCKER=1` — для Docker Compose).

## Конфигурация

| Файл | Что в нём |
|---|---|
| `.env` (из `.env.example`) | Секреты и пути: `TELEGRAM_BOT_TOKEN`, `OWNER_TELEGRAM_ID`, `MASTER_KEY`, `DATABASE_PATH`, `BACKUP_DIR`, `LOCK_PATH`, ключи ИИ (этап B), Google OAuth (этап C) |
| `config/app.yaml` (из `config/app.example.yaml`) | Поведение: лимит 4/60 и категории, планировщик, интервалы напоминаний, бэкапы, срок подтверждений. Без файла — умолчания |
| `config/ai.yaml` (из `config/ai.example.yaml`) | ИИ-провайдеры, модели, маршрутизация (этап B). Без файла — режим без ИИ |

Личные параметры (часовой пояс, тишина, время отчётов, характер) задаются в боте и хранятся
в базе. Значения, которые ТЗ не утвердило, не выдумываются — см. `docs/open-questions.md`.

## Разработка и тесты

```sh
uv run pytest -q
uv run ruff check src tests && uv run ruff format src tests
uv run pyright
```

Тесты не ходят в сеть: Telegram API подменяется (`procbot.testing.MockedBotSession`), время
фиксируется (`FrozenClock`), ИИ — адаптер `fake`. Ключевые проверки: доступ только владельцу,
дедупликация update, лимит 4/60, тишина/пауза, DST, перезапуск, бэкап → восстановление на
чистом пути, соответствие миграций моделям.

## Известные ограничения

- Бэкап шифруется целиком в памяти (Fernet не потоковый) — нормально для личной базы
  размером в десятки мегабайт.
- Ротации `MASTER_KEY` пока нет; потеря ключа = потеря доступа к бэкапам и секретам.
- Копии бэкапов вне сервера и оповещение о падении не настроены (открытый вопрос № 10).
- Бэкап содержит только базу; `config/*.yaml` и `.env` храните отдельно.
